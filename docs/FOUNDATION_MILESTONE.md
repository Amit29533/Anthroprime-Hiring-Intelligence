Candidate navigation uses UUIDs; Anthro-ID stays the compact display identifier. Demand/client search links use their entity UUIDs. Missing navigation callbacks disable their buttons. Features mount only for internal admin/recruiter/viewer cloud accounts, and component state resets on workspace/role changes. They add no service, Netlify function, provider, environment variable or package dependency.

## Contracts and limits

The public invoker RPC is `api_foundation(p_action text, p_payload jsonb, p_offset integer, p_operation uuid)`. Its guarded private console checks current workspace membership on every request. Helpers and raw private tables are ungranted; private tables have RLS. Privileged MFA follows existing policy. Workspace-bound source heads and actor-bound operation UUIDs protect writes; exact retries return their receipt, while changed payloads or changed privilege projections conflict. Lost acknowledgement locks the review payload and exposes exact retry or explicit discard. Refresh failure after acknowledged success does not repeat a write.

| Operation | Admin | Recruiter | Viewer | Assigned assessor/sales/external/anonymous |
| --- | --- | --- | --- | --- |
| Professional filters, discovery, search, aggregate reports and history | Yes | Yes | Yes | Denied |
| Personal view save/delete | Own views | Own views | Own views | Denied |
| Expected pay criteria/counts | Yes, declared units and MFA policy | Denied | Denied | Denied |
| Quality review and aggregate export | Yes, MFA policy | Yes | Denied | Denied |
| Task assignment/completion | Any current task, MFA policy | Own task; claim blank task to self | Denied | Denied |

Custom fields remain existing workspace-visible metadata. Their labels do not create financial access restrictions. A field ID derives from its immutable candidate definition name; its version changes with the definition. All uses remain bound to the selected workspace. Archived/changed criteria remain visible in saved views but must be corrected before running; role-downgraded financial views are restricted and redact their financial criteria.

Filters accept existing flat documents or `{version:1,base:{...},custom:[...]}`. Maximum eight custom predicates, 4,000 filter bytes, 12,000 request bytes and 40 definitions per module. Numeric criteria are finite JSON numbers up to absolute 10^15; dates are ISO dates; choices require exact active options. Blank/null values are missing; zero is known. Text search is literal, not SQL wildcard syntax. Base criteria cover name/skills/Anthro-ID, location, employer, exact skill/tag, status, engagement, mode, experience, notice and four repository sorts. Keyset cursors bind workspace, criteria and sort with UUID tie-breakers. Counts scan the current matching population; a cursor is not a frozen database snapshot. Concurrent sort-key edits require refreshing the live result.

Administrative expected-pay filtering uses the latest applicable, nonsuperseded observation across the identity family: confirmed, observed no later than UTC today, at most 120 days old, currency-unit amounts, exact currency and Annual/Monthly/Hourly/Daily basis. Missing/unlike units fail; an older passing amount cannot override a newer applicable amount. Staff search and similarity exclude financial values, contacts and private documents/evaluations.

Discovery evaluates the first **1,000 matching active unheld identities by UUID**, then ranks and returns 25 at a time. It states total, evaluated count and whether coverage is bounded. It does not find the global best 1,000 across an arbitrarily large workspace. Demand professional weights exclude budget and normalize the remaining weights; profile experience/notice/location are descriptive observations. Hard requirements use existing confirmed demand-journey checks, with unknown preserved (including empty requirements or private compensation checks). Readiness comes from the existing validated journal. Eligible/ready controls refine the evaluated sample, not the entire workspace. Later pages re-evaluate and reject changed source heads. Evidence exceeding 2 MB fails with an instruction to narrow criteria.

Reports use that same evaluated identity denominator, and reject hidden eligibility/readiness exclusions. Groups retain full-value identity while labels display at most 120 characters, so long labels and literal “Unknown” do not merge with missing data. At most 40 groups and 50 demand skills are returned with omitted counts. Heat-map weights distribute the demand's skill weight equally; observed missing skills are not independently validated gaps. Reuse is at least two distinct demands with Active/Completed/Terminated placements across the reviewed identity family; it is not conversion or commercial performance. No-demand reports retain unknown eligibility and zero validated-ready counts. Export is a source-checked aggregate JSON snapshot with operation/scope/time evidence, no candidate rows, six new exports per actor/workspace/minute and exact receipt replay. Prepare and download are separate actions.

Quality decisions preserve source evidence. Reviewed/Deferred/Reopened are human dispositions; Needs review means the source changed. Corrected means a recorded finding is no longer present, awaiting explicit resolution. Resolved is allowed only after source correction and rejects a still-present finding. Reasons are 10–1,000 characters. No arbitrary taxonomy target is labelled incorrect because built-in vocabulary is client-side. Import findings show row/status, not staged payloads or raw private errors. Reviewing duplicate import rows does not merge candidates or rewrite identity/history.

Context selectors list the first 100 demands and 200 internal editors; manual UUID inputs handle records beyond those lists. Task handoffs require a current internal editor UUID. Admins or current owners may reassign/complete; recruiters may claim a blank task only to themselves. Assignment UUIDs are recorded in the journal and survive Auth email changes; the public owner email remains a legacy display bridge. Membership revocation is checked again. Unrecognized legacy owner labels need administrator reconciliation; they are not treated as claimable blanks. A database trigger applies ownership rules to older owner/completion writers too. Existing task creation and legacy history remain compatible; detailed review reasons belong to the new handoff workflow. Task pages filter all/mine/unassigned, pending/completed, overdue/next 30 days/undated, and literal title. Quality/task/search offsets are capped at 10,000 and histories at 25 rows per page; source heads protect decisions, while these offset queues are live and can reorder after changes.

## Migration, lifecycle and privacy

Apply the CLI-generated additive [foundation migration](../supabase/migrations/20261008035834_foundation_milestone.sql) after every earlier migration. It adds private `views`, `quality_events`, `task_events` and `receipts`, target/candidate/quota indexes, an owner/due task index and the ownership guard. Existing tenant indexes bound base access; custom predicates run server-side and currently require scanning within that tenant. No speculative custom JSON index is added. Local EXPLAIN inspection validates journal query compilation, not hosted performance or index selection at production volume.

New candidate-linked journals and receipts join formal D7 inventory (**63 categories**) and operations dry-run source inventory (**60 categories**). Old captured scopes must be recaptured. D6 scope notices explicitly exclude these new internal journals/receipts; regenerate prepared reviewed disclosure packages after the notice changes. Personal saved filters are actor metadata rather than per-candidate records. Reviewed merges retain historic candidate links; identity-family inventory includes those links, and retired task identities must be reconciled before a new handoff. Holds exclude discovery/report populations; governance review and professional repository reads remain available under existing rules. No destructive erasure executor is enabled.

A full recovery backup must include all private schemas, operation receipts, journal identity sequence state, public task state, Auth identities and existing private objects. App JSON exports do not constitute that backup. There is no new outbound work or automatic transfer of communication/assessment outcomes during merge.
