## Built during this continuation

The remaining permission work deserves early priority: the legacy full-workspace adapter still uses `select('*')`, and the baseline compensation-history read policy grants workspace members access. Narrow paged projections and administrator-only financial controls in reports do not establish field isolation throughout the legacy routes or direct Data API. Define the intended financial/assessor/account permission matrix, then change database projections and all legacy consumers together; test raw API responses and historical snapshots rather than relying on hidden controls. This continuation's quality projection deliberately contains no compensation fields, but it does not rewrite that broader legacy access contract.

### 1. Bounded repository quality review

Cloud **Repository overview** now includes a quality panel. `api_repository_quality` returns at most 25 projected rows per page with exact full-queue counts and a distinct affected-candidate count. Findings can overlap; totals are not page sizes or a sum of queues. Traversal uses name/UUID cursors bound to queue and server UTC date. Changing the queue or day requires a fresh traversal. Merged identities are excluded; opening a finding uses the existing Candidate 360 workflow.

Queues: missing primary email, missing primary phone, unknown notice period, recorded profile date older than 120 days/unknown, future profile dates, and absence of current validated skill evidence. A primary contact can be missing despite an alternate contact; promotion remains pending. Zero days of notice is known, not missing. Profile dates are recorded facts and do not attest that every field was verified.

Skill findings read the actual `skillEvidence` observations joined to workspace-scoped `personSkills`, including evidence retained under merged identities in the current candidate's family. Qualifying evidence has weight at least 70 and an observation timestamp between UTC midnight 365 days ago and now. These are stored evidence dates, not independent verification of the observation. A fresh self-declaration cannot renew an old validated observation, and future evidence is excluded. This finding does not establish skill relevance, proficiency sufficiency, demand fit or assessed readiness; all require their existing/separate review.

Projection: candidate UUID, Anthro-ID, bounded name, profile date and finding codes only. No complete contact, compensation, custom, document, history or evidence objects reach this response. Members can read; anonymous, external-client-only and other-workspace reads are denied. Private helper execution rechecks current membership, uses fixed workspace predicates on every join and an empty search path. No new candidate-linked record or privacy inventory category is created; D7 remains at 38 categories and D6 retains its existing exclusions.

### 2. Anthro-ID capacity monitoring

Administrators see `api_anthro_id_capacity` telemetry from the existing **global** 99,999-position sequence. It reports consumed positions and remaining allocations, with warnings at 90,000 consumed, critical status at 95,000 and exhaustion at 99,999. Recruiters/viewers are denied at the database, not merely hidden in UI. It returns no other workspace's candidate records.

Monitoring never calls `nextval`, resets the sequence, reallocates an ID or changes UUID relationships. Consumption is not live candidate count: merges, deleted rows and failed/non-transactional allocations do not restore capacity. The `is_called=false` state is accounted for. Warnings are inside the app; there is no external alert sender. Expanding the namespace requires a separately designed compatibility migration that preserves existing identities. The existing allocator and its sequence privileges are unchanged by this telemetry slice.

### 3. Broken legacy cloud anonymization action

The legacy retention scrubber sets `anonymized`, but the current candidate database schema has no such column. Its cloud upsert would fail; even its demo transformation leaves linked files/history and does not establish privacy fulfillment. Cloud **Anonymize** is now disabled with an explanation directing administrators to subject-request and erasure-scope review. Existing fictional demo behavior remains. The retention period still controls a review queue, not an automatic deletion policy. No replacement destructive action is introduced.

## Activation and verification

Apply all migrations in filename order through `20261007120440_repository_quality_and_identity_capacity.sql`. No new service, package, Netlify function, provider credential or environment variable is introduced. Existing cloud/paged routing applies. Work is committed locally only; nothing is deployed or pushed.

Focused checks cover cursor ties and no duplicate traversal, global counts versus 25-row pages, overlapping findings, merged/tenant exclusions, zero notice, 365-day evidence boundaries, old validated evidence plus new self-declaration, future evidence/dates, narrow projections, role and membership removal, non-allocating sequence telemetry, burned allocations and all warning thresholds. UI checks cover page/filter reset, malformed/error responses, candidate navigation, admin-only telemetry and cloud anonymization being disabled without a write. Migration reapplication is exercised.

The existing client privacy regression assertion was corrected: searching every JSON byte for salary-number substrings can mistake approval timestamps for a financial leak. It now recursively rejects prohibited field names and checks the known contact value. Client projection and authorization behavior are unchanged.

Hosted security/performance advisors, Auth/PostgREST roles, true concurrent-session behavior and representative workload acceptance remain pending. Quality totals compute findings in the database; bounded browser payloads do not imply constant-time database scans. Sequence readings are a point-in-time operational metric and can change immediately after concurrent allocations.

Final local verification: **803 Node regression tests and four OCR tests passed**. Lint, changed-file formatting, documentation links and offline Netlify packaging of all 17 existing functions passed; the main entry remains 65.4 KiB under its 100 KiB budget. Local Supabase advisors could not connect to `127.0.0.1:54322`. The earlier full run had one false-positive client privacy assertion; the final full run passed after its correction and the merged-evidence check.
