# Roadmap features: current stack versus additional dependencies

Implementation has started under [five current-stack build phases](CURRENT_STACK_BUILD_PHASES.md). Track actual completed slices there.

Date: 7 October 2026. Companion to the [five-stage roadmap](FIVE_STAGE_PRODUCT_ROADMAP_2026_10_07.md).

**Can implement now** means development can proceed using this project's existing architecture: React/Vite on Netlify, Netlify functions, Supabase for database/auth and private R2/object storage where files are involved. It does not mean Netlify alone supplies the database, that every feature already exists, that account configuration has been verified, or that production activation is complete. All cloud features require existing credentials, migrations and hosted permission tests.

**Needs additional things** identifies an external provider/account, persistent worker compute, recovery infrastructure or an approved operating decision. In many cases the UI, schema and test adapter can be built now, while the live capability waits for that dependency.

## Netlify execution and service boundaries

Netlify supports scheduled functions, and background functions can run up to 15 minutes. Use leases, database receipts and bounded resumable batches; a background invocation is not a persistent worker service. Scheduled execution also needs verification on the deployed production site. [Scheduled functions](https://docs.netlify.com/build/functions/scheduled-functions/), [background functions](https://docs.netlify.com/build/functions/background-functions/)

The current [deployment contract](NETLIFY_DEPLOYMENT.md) already separates frontend/API hosting from Supabase data/auth, private originals and Docker scan/OCR workers. New credential-based integrations do not require moving the frontend away from Netlify.

VirusTotal's public API prohibits commercial product/service use and certain business workflows. Keep private ClamAV as the scanning foundation; unknown hash reputation is not a clean antivirus scan. [VirusTotal restrictions](https://docs.virustotal.com/reference/public-vs-premium-api)

Database backup coverage is different from original-file backup coverage: Supabase database backups do not include Storage object bytes. Backup both database and originals, and verify actual plan capabilities. [Supabase backups](https://supabase.com/docs/guides/platform/backups)

## Recommended build order

First complete paged saved views/editing, verified candidate facts and role projections. Then implement structured scorecards/readiness, useful reports and client review using the existing stack. Build communication interfaces and test adapters alongside these; activate email/calendar after provider setup. Preserve private scanning/recovery/policy gates before a live candidate pilot, even while dependency-free development continues.

This split changes prioritization, not implementation status. No providers were configured or features activated as part of this document. Continue committing locally only; do not push to GitHub.
